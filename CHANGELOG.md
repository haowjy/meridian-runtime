## [0.5.0] - 2026-11-16

### Upgrade notes

- Add `reasoningLevels` to the `createGateway` config: the ladder your levels sit on, lowest first (for example `["none", "minimal", "low", "medium", "high", "xhigh", "max"]`).
- Fill each model's `reasoning.efforts` from its row, including `xhigh`, and list `none` for a model that can switch off (or has a models.dev `toggle`). Delete `canDisable`.
- Pass `reasoning: "<level>"` instead of `{ effort }`; `"disabled"` becomes `"none"`; drop `"adaptive"`.
- To keep today's Gemini 3 behaviour, set `functionCallIds: true` on each Gemini 3 and later model. Unset, a model gets the older protocol (no call ids, no media in a function response; a tool result with media throws).
- Replace uses of the two cache TTL constants with your own numbers.

### Changed

- Reasoning levels are data, not a package list. `ReasoningSupport` is `{ efforts: readonly string[]; thinksByDefault?: true }`: the model's own levels, lowest first, where `none` means it can switch reasoning off. `canDisable` is gone.
- `GenerateRequest.reasoning` is a level name (`string`); absent means the model's own default. The `"disabled"`, `"adaptive"` and `{ effort }` forms are gone (`disabled` is `"none"`, `adaptive` is absent).
- `ResolvedReasoning` is `"default" | { effort: string }`; `effort: "none"` means off.
- `resolveReasoning(requested, support, levels)` is the one rule and is exported from `./gateway` (browser-safe) so a UI can show the level a call will run at. A listed level is used as asked; otherwise the nearest listed level on `levels` (a tie goes up, never onto `none` unless `none` was asked); with nothing to pick, the model's default.
- Adapters send every level as written and translate only `none`. Gemini now sends `thinkingLevel` upper-cased (so `xhigh` reaches `XHIGH`, and `max` is no longer turned into `HIGH`).

- No gateway or adapter code reads a model id any more. `ModelInfo` gains `functionCallIds?: true` (function calls carry ids their results pair with; on the Gemini wire that means an `id` on each function call, media allowed in a function response, and `skip_thought_signature_validator` on a replayed first call without a signature). `geminiMajorVersion` and the Anthropic context-window page cap are deleted; a PDF is held only to the token-fit check.
- OpenAI-compatible sends every level as `reasoning_effort`, `none` included (it sent nothing for `none` before).
- A reasoning model whose row lists no level gets the model's default for any request: such models take no effort parameter on the wire. This is the one place `resolveReasoning` differs from Mars's `resolveEffort`; it is documented on the function.

### Removed

- `REASONING_EFFORTS`, `ReasoningEffort`, `DEFAULT_SUBAGENT_PROMPT_CACHE_TTL` and `DEFAULT_PRIMARY_PROMPT_CACHE_TTL`. Cache lifetimes are the host's data.

## [0.4.0] - 2026-11-16

### Added

- `@meridian-flow/runtime/script`: the script port (`ScriptRunner`, `ScriptRequest`, `ScriptResult`, `HostFunction`, `HostFunctionError`, `Json`). A script is JavaScript a model wrote that calls functions the host hands it and returns one JSON value; every outcome (returned, threw, timed out, too large, aborted, unavailable) is a result, never a throw. No Node built-ins.
- `@meridian-flow/runtime/script/quickjs`: `createQuickJsRunner`, which runs each script in QuickJS compiled to WebAssembly, in its own worker thread. Limits on wall time, script CPU time, host calls, call size, value size, log size and memory. Needs Node 22 or newer (`engines` says so). Creating the runner throws if the worker file or the `.wasm` is missing, so a bad bundle fails at server start. A host that bundles its server must keep this package external (Nitro: `traceDeps`).
- `@meridian-flow/runtime/script/testing`: the conformance suite every script runner passes, and a scripted fake runner (`vitest` is an optional peer).

## [0.3.0] - 2026-11-16

### Added

- `@meridian-flow/runtime/mcp`: `createMcpClient` (`list`, `call`, `check`, `close`), `pin`, `pinHash`, `toTools`, `toCatalogue`, `describeTool` and `toContent`. A call returns an outcome (`answered`, `rejected`, `too_large`, `unreachable`, `aborted`) decided from the raw reply on the wire, so a tool that ran is never reported as failed because the MCP SDK rejected its reply. Needs Node.

## [0.2.0] - 2026-11-15

### Changed

- Requires Node 22 or newer (`engines.node`), because both provider SDKs now do.
- Anthropic: an API key now goes out as `Authorization: Bearer` instead of `X-Api-Key` (Anthropic SDK 1.x). Anthropic accepts both; an Anthropic-compatible endpoint behind `baseUrl` that reads only `X-Api-Key` will stop seeing the key. DeepSeek's Anthropic endpoint works.
- Dependencies: `@anthropic-ai/sdk` 1.8, `openai` 7.57.
- Types: `Message` is a union by role. An assistant message holds only text, reasoning and tool-use parts (`AssistantContentPart`); a `media` part there no longer type-checks. No provider took it: OpenAI Responses and Chat Completions would have sent `input_image`/`image_url` in an assistant message, Gemini dropped it, and Anthropic's new API version rejects the `document` block it became. A `system` or `user` message holds text and media parts, and a `tool` message holds only tool results. `assistant()` takes `AssistantContentPart[]`. Code that reads `content` across roles needs the element type spelled out, for example `messages.flatMap((m): ContentPart[] => m.content)`.

### Fixed

- The Anthropic SDK's OpenTelemetry tracing, on by default since SDK 0.134 and configured from `ANTHROPIC_OPEN_TELEMETRY*` variables, is turned off, so the package still reads no environment variable.
